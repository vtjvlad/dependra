# Журнал архитектурных решений (ADR)

Официальный источник **почему** принято решение. Спека **что** делать — в [`docs/`](../../docs/README.md).

## Документы

- [template.md](template.md) — структура записи
- Правила ниже — когда создавать / не создавать

## Когда создавать ADR

- Изменение архитектуры или структуры проекта
- Выбор / смена технологии (например, AST-парсер)
- Отказ от решения
- Изменение принципов взаимодействия модулей
- Изменение внутреннего формата данных / CLI / плагинов / формата документации
- Любое решение, которое позже вызовет вопрос «почему так»

## Когда НЕ создавать

- Мелкие багфиксы, рефакторинги, комментарии, имена локальных переменных, мелкие оптимизации

## Процесс

1. Создать файл `ADR-NNNN-short-title.md` по шаблону (NNNN — порядковый номер).
2. Статус: `Предложено` → `На обсуждении` → `Принято` (или `Отменено` / `Заменено`).
3. При замене указать ссылку на новый ADR.
4. Не переписывать историю принятых ADR молча — фиксировать замену.
