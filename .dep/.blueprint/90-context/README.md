# Контекст проекта

## Создать отдельный файл постоянного контекста проекта.

Данный файл предназначен для хранения информации, необходимой для дальнейшей разработки.

Его задача — максимально снизить необходимость повторного анализа истории переписки.

### Файл должен содержать:

* общую концепцию проекта;
* архитектурные решения;
* принятые соглашения;
* правила кодирования;
* правила оформления;
* структуру проекта;o
* соглашения по именованию;
* список принятых технологий;
* ограничения проекта;
* текущие договоренности;
* долгосрочные цели;
* особенности реализации;
* требования к качеству;
* правила взаимодействия между модулями;
* требования к документации;
* принятые проектные решения;
* причины принятия важных решений.

Дополнительно допускается хранение:

* кратких итогов обсуждений;
* истории изменения архитектуры;
* причин отказа от определенных решений;
* важных рекомендаций.

Этот файл не является логом переписки.

Это индекс знаний проекта.

Он должен содержать только ту информацию, которая действительно помогает продолжать разработку без повторного анализа предыдущих обсуждений.

При каждом существенном изменении архитектуры или концепции проекта данный файл должен обновляться.

Обновление должно происходить только после подтверждения владельцем проекта.

Файл должен быть максимально структурирован, легко читаем и пригоден для дальнейшего использования как основная база знаний проекта.
