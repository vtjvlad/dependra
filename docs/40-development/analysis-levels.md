# Уровни анализа

## Цель

Пользователь выбирает глубину анализа. Уровни — **конфигурация**, не жёстко зашитая логика в ядре. Набор уровней может меняться.

## MVP (0.0.1)

| Level | Содержание |
|-------|------------|
| **1** | Минимальная информация о файле (`--basic`) |
| **2** | Level 1 + (в будущем) окружение/FS extras; **сейчас** эквивалентен basic, пока deferred-P не реализован |
| **3** | Level 1 + импорты + экспорты + зависимости (`--basic --imports --exports --graph`) |

Флаг `--level <n>` — **опционален** для MVP; достаточно комбинации флагов операций. Если добавляется `--level`, он включает набор операций по таблице.

## Deferred

| Level | Идея |
|-------|------|
| **4** | AST-глубина, базовый quality, структура файла |
| **5** | Проект целиком, графы, визуализация, архитектурные нарушения, комплексные отчёты |

## Правила

- Можно добавлять уровни и менять состав без переписывания ядра (композиция инспекторов).
- Включать/отключать анализаторы конфигурацией.

## Acceptance criteria

- [ ] Level 3 покрывается комбинацией MVP-флагов
- [ ] Level 4–5 не реализованы и помечены deferred
