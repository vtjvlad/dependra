# Минимально необходимая реализация

## Правила

1. Запрещается создавать код «на будущее», который нигде не используется.
2. Не создавать пустые классы, интерфейсы, абстракции и модули только потому, что они могут понадобиться позже.
3. Каждая реализованная сущность используется в текущей версии (`0.0.1` этап).
4. Архитектура проектируется так, чтобы новые возможности добавлялись **без изменения ядра**.
5. Баланс: простота текущей реализации ↔ расширяемость.
6. Избегать преждевременного усложнения.

## Связь с деревом src/

Каталоги из [project-structure.md](../20-architecture/project-structure.md) создаются по мере появления кода, а не заранее пустыми.

## Acceptance criteria

- [ ] В PR нет мёртвого кода и пустых модулей-заглушек без вызова
