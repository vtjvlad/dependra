# Ограничения архитектуры

## Запрещается

- Создавать монолитные компоненты
- Объединять несколько независимых обязанностей в одном модуле
- Циклические зависимости между модулями
- Обращение к внутренней реализации других модулей
- Нарушение уровней абстракции
- Дублирование функциональности между независимыми компонентами
- Скрытые зависимости
- Временные архитектурные «костыли» как постоянные решения
- Функциональность, нарушающая принципы модульности
- Regex вместо AST для анализа импортов/экспортов JS
- TypeScript и фреймворки в ядре (см. [stack.md](../10-technology/stack.md))

## Рекомендации

- Новый модуль предпочтительнее размывания ответственности существующего
- Композиция вместо переписывания готовой логики
- Общие механизмы — в отдельные модули
- Сохранять совместимость публичных интерфейсов; несовместимость — через версию + ADR
- Сначала оценить влияние на границы модулей, потом менять дерево каталогов
- Операции: независимость, повторяемость, включение в разные сценарии
