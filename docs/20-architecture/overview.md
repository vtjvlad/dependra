# Архитектура — обзор

## Цель

Dependra строится как **модульная** система: масштабируемость, расширяемость, независимость компонентов, простота сопровождения.

Структура каталогов отражает архитектурную модель, а не удобство разовой реализации. Монолитная архитектура запрещена.

## Принципы (обязательные)

1. **Модульность и SRP** — один модуль = одна ответственность.
2. **Контракты** — публичный API, схемы входа/выхода, ошибки, версия интерфейса.
3. **Изоляция реализации** — снаружи только контракт.
4. **Слабая связанность** — без циклов и скрытых зависимостей.
5. **Расширяемость** — новые инспекторы/операции без правки ядра.
6. **Композиция операций** — операции независимы и комбинируемы.
7. **Повторное использование** — общие механизмы выделять в отдельные модули.
